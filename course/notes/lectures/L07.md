## AMAT 必须先说清单位与分母

单级简式为 `hit_time + miss_rate × miss_penalty`，这里 penalty 指在命中时间之外增加的等待。若给的是 miss 的总服务时间，不能再重复加同一部分。纳秒与 CPU 周期先换成相同单位。

两级可写 `t1 + m1 × (t2 + m2_local × p_memory)`，前提是各项按串行访问模型定义。L2 local rate 的分母是到达 L2 的访问；global rate 的分母是 CPU 总访问。这个 AMAT 不直接等于乱序程序暴露的总停顿，重叠能力之后另分析。

## 写入没有一个万能策略

write-back 行可能包含比内存更新的数据，dirty 逐出时必须处理；write-through 把每次写传播下去，也可以用 buffer 隐藏部分等待。write-allocate 与否是另一个决策，不能把常见搭配当作唯一合法组合。

write buffer 中可能已经有一份更新值。如果读 miss 越过它去内存取旧值，会破坏语义；实现可等待、比较地址并转发等。相同地址存在多次待写时，还要选程序顺序上应看到的最新一次。

3C 分析要固定行大小、容量、替换规则及比较基准。增加行大小会减少行数，预取会改变需求访问之前的状态，不能只机械套一个箭头。第 23 页的包含关系先按数据块集合理解；最新数据/dirty 的维护还需写策略和一致性规则配合。

## 基础自检（约 10–15 分钟）

1. 两行全相联、初始空，访问 `A,B,A,C`。末次访问替换谁？分别用 LRU 和 FIFO 解释。
2. write-back cache 的 dirty 行被逐出时，为什么不能直接丢弃？若是 clean 行呢？
3. CPU 共访问 1000 次，100 次到 L2，20 次最终到内存。算 L1 miss rate、L2 local rate、L2 global rate。

## 补缺／迁移（选做，实践后）

1. t1=1 ns、m1=10%、t2=6 ns、m2_local=25%、额外主存 penalty=40 ns。算串行模型 AMAT；为什么不能把它直接乘全部指令数？
2. 待写缓冲保存 `X←7`，下层仍为 X=3；年轻 load X 出现。提出正确处理，并说明把 L1/L2 改成 inclusive 是否自动解决此问题。
