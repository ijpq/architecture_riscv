## 为什么翻译和 cache 能同时开始

VA 与对应 PA 的页内 offset 相同。如果 cache 的所有 index 位和 block offset 位都在页内，数据阵列可以直接拿 VA 索引，同时 TLB 查 PPN；随后用 PA tag 验证。这就是此处的 **virtually indexed, physically tagged**。

在普通、无额外别名机制的组织中：

```text
index_bits + block_offset_bits ≤ page_offset_bits
数据容量 / ways ≤ page_size
```

例：4 KiB 页、64 B 行、8-way、32 KiB cache，有 64 组；6 bit index+6 bit block offset=12，恰好不超过页内 12 bit。增加 way 可在不增加 index 位的情况下扩大容量，但比较/选路开销也会变。

## 同名、别名与失效不能混用

两个进程相同 VA 可以映射到不同 PA；在虚拟 tag 或 TLB 中，需要 ASID/上下文信息或切换失效。两个不同 VA 也可能指向同一 PA，若缓存出两份独立副本，写一份后另一份可能过时；仅加 ASID 不自动解决这种别名。

ASID 允许不同进程翻译共存，却不让已经改变的 PTE 自动更新所有 TLB。页表修改、ASID 重用和跨核失效仍需按系统规则维护。精确异常用于在页表/权限问题处理后恢复正确指令，不是“所有缺失都清空流水线”的同义词。

第 26–27 页关于 GPU/嵌入式 VM 使用的表述有历史范围，不能推广成今天所有 GPU 都不支持按需分页。系统 VM 的两阶段翻译在 [补课导读](L20-supplement.md) 另外学习。

## 基础自检（约 10–15 分钟）

1. 4 KiB 页、64 B 行、8-way：32 KiB 与 64 KiB 的 cache 哪个满足上述简单 VIPT 条件？写出位数。
2. 同一个物理页通过 VA1、VA2 映射出来，为什么可能产生两个不一致副本？这与两个进程都使用 VA=`0x1000` 有何区别？
3. 一次 load 的 TLB miss、权限拒绝和数据 cache miss，分别应该到哪种后续处理？

<details>
<summary>完成后核对要点</summary>

1. 32 KiB 的 index+offset=6+6=12；64 KiB 为 7+6=13，后者需额外机制或改组织。
2. 前者是同 PA 的别名；后者可能是同 VA 不同 PA 的上下文区分。ASID 主要帮助后者。
3. 合法映射 miss 可 refill；权限拒绝走故障处理；cache miss 到下层取数据，不能互相代称。

</details>

## 补缺／迁移（选做，实践后）

1. 若固定 64 KiB、64 B 行、4 KiB 页，最低多少 way 能满足简单 VIPT 条件？指出这不是没有代价的万能方案。
2. OS 将某页从可写改只读，页表已更新但一个核还保留旧的可写 TLB 项。解释为什么必须处理旧项，以及 ASID 不变时何以仍会出错。

<details>
<summary>检查方向</summary>

至少 16-way，`64 KiB/16=4 KiB`；还需比较/访问时间、能耗与成本。旧 TLB 权限可继续允许非法写，必须通过架构规定的同步/失效流程维护；进程标识正确不等于映射仍然有效。

</details>
