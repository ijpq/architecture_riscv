## 1. 从单核并行到共享内存多核

流水线、乱序与向量主要挖掘一个指令流中的并行性；多核要求程序分解出多个指令流。共享内存让线程通过同一地址空间通信，但并不会自动替程序分配工作、避免竞争或保证正确结果。

先画任务依赖图：哪些计算相互独立，哪些数据必须先由另一个线程产生？理想加速会受到串行部分、负载不平衡、通信、同步和共享带宽限制。用 Amdahl 定律算上界，再解释真实测量为何达不到上界。把线程数从 1 改成 2，只是增加资源，不代表程序真的并行完成了一半工作。

缓存行是很多一致性操作的基本粒度。两个线程改写不同变量但变量同处一行，会产生伪共享；同一变量未同步的冲突访问则是数据竞争。二者可能同时存在，不能靠加 padding 修复程序语义错误。

**过渡练习：**设计一个不需要共享累加器的向量加工作划分；说明尾部如何处理、每个输出由谁负责、何时能宣布结果完成。先做纸面设计，不照抄优化代码。

## 2. 虚拟内存不是虚拟机

进程虚拟内存把进程虚拟地址转换为物理地址并执行访问保护。虚拟机还要为 guest 操作系统提供受控的 CPU、特权操作、中断、地址空间和设备视图。guest 内核不是 host 内核；guest 自认为的物理地址也不必是机器真正的物理地址。

可以用三层表示地址：

```text
guest virtual address → guest physical address → host/machine physical address
```

这只是模型示意，具体 ISA 的术语和硬件支持不同。不要把现代 RISC-V hypervisor 扩展的细节强套到旧讲义中的另一 ISA。

## 3. 两类地址管理办法

- **Shadow page table：**虚拟机监控器维护硬件实际使用的影子映射。guest 修改页表时，监控器需要保持影子内容正确；减少硬件复杂度的同时增加了维护成本。
- **两阶段转换：**硬件将 guest 自己的页表转换与第二阶段映射组合起来。TLB 可以缓存组合结果，miss 后的遍历成本可能明显增加；不能把所有访问都按最坏遍历次数计算。

这里要掌握的是“映射归谁管理、权限在哪检查、失效怎样传播”，而不是背某个固定的页表访问数字。若要计算次数，先明确页表级数、哪些页表访问也需第二阶段转换、TLB 和各级页表缓存是否命中。

## 4. 特权操作与设备

guest 执行敏感操作时，监控器可能需要截获并模拟，或者由硬件机制安全处理。设备虚拟化还涉及中断、DMA 和 I/O 隔离；地址空间的 CPU 保护并不自动约束设备 DMA。虚拟化的隔离目标和性能开销应分别讨论。

## 自测（本地补充题，不是官方作业）

- 为什么 guest 的物理地址不能直接等同于 host 的物理地址？
- 更大页能减少哪些转换压力，又会带来什么粒度或空间代价？
- 一个 cache coherence 协议能否代替页表权限检查？为什么？
- 为什么“两个核执行结果正确”还不足以证明同步适用于所有允许的内存顺序？
