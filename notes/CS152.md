## L01：体系结构背景与 ISA

原件：[L01 Introduction](../course/originals/sp23/lectures/L01-Intro.pdf)。

L01 的主体是课程介绍、技术背景和计算机发展史，穿插体系结构抽象及软件兼容性。CPU 时间、CPI、Amdahl 定律可作补充复习，但不是这份 L01 原讲义的主要教学内容。

### ISA 与微架构

ISA 是软件可观察到的接口：指令编码与语义、程序员可见的寄存器状态、数据和访存规则，以及规定的异常行为。

微架构是实现这套接口的内部组织与执行方式，包括数据通路、控制器、流水线、调度和存储层次等。相同 ISA 可以有单周期、多周期、流水线或乱序等不同实现；微架构也不必使用微码。

例如，RISC-V 的 `add x3, x1, x2` 规定寄存器加法的结果，而 ALU 怎样连接、分几拍执行、能否与其他指令重叠，是实现层面的选择。

### IBM 360 以前也有 ISA

IBM 650、IBM 701 等早期机器已经有指令系统。IBM 360 的重要性在于将共同的程序员可见架构作为跨性能档次产品系列的稳定软件兼容接口，而不是首次发明了指令集或软件兼容。

讲义比较了 IBM 360 的 8 位与 64 位数据通路及不同控制实现。程序可见的寄存器宽度，不要求所有内部通路具有相同宽度；较窄通路可以分段完成较宽的运算。

### 早期程序怎样依赖硬件

IBM 不同产品家族曾使用不同的指令、数据格式、I/O 系统与软件工具链。已有机器码不能仅因厂商相同就在其他架构上直接运行。

IBM 650 还体现了程序布局对机械时序的依赖。其 10 位十进制指令字含两位操作码、四位数据地址、四位下一条指令地址。程序员安排指令在磁鼓上的位置，使下一条指令尽量在当前操作结束时转到磁头附近。

这里要区分程序兼容与性能优化：稳定 ISA 可以保持规定的程序行为，运行速度与布局优化仍会受具体硬件影响。

## L02：RISC-V 也可以采用微码控制

原件：[L02 Simple Implementations](../course/originals/sp23/lectures/L02-SimpleImps.pdf)。

第 14 页列出的 “RISC → hardwired, pipelined” 是常见设计搭配，而不是 ISA 的强制要求。RISC-V 规定指令行为，硬连线或微码决定控制信号怎样产生。两者是不同维度。

第 17 页的微码 CPU 包含主存、微码 ROM、微程序计数器 `µPC` 与数据通路：

- 主存保存普通 RISC-V 程序；PC 指向程序指令。
- 微码 ROM 保存微指令；µPC 选择下一条微指令。
- 微指令的控制字段经解码后，驱动寄存器、总线、ALU 与存储器接口。

微指令是控制字；微程序由这些步骤组成，实现一条 ISA 指令。它与普通 RISC-V 机器指令不同，一条微指令可以同时控制多个部件。

硬连线控制和微码控制都使用实际逻辑电路。这里的 hardwired 指控制器实现方式，不是“实际电路”的统称。

## L02 第 23 页：单总线数据通路

第 23 页介绍同一台微码 RISC-V CPU 的数据通路。底部的 “means” 是把寄存器传送写法展开成控制信号，不是在两台 hardwired/microcoded CPU 之间转换。

### 部件与信号

- **MA（Memory Address Register）**：内存地址寄存器，输出连接主存的地址输入。
- **A、B**：ALU 的输入暂存寄存器，不是 RISC-V 的通用寄存器别名。
- **IR（Instruction Register）**：保存取出的普通 RISC-V 指令。
- **RegSel**：在 `rs1`、`rs2`、`rd` 或 PC 对应的位置之间选择寄存器 RAM 地址。
- **RegW**：寄存器 RAM 写控制；本步取 PC 时为 0。
- **RegEn**：寄存器 RAM 的输出使能，允许所选值驱动共享总线。
- **MALd、ALd、BLd、InstLd**：允许相应寄存器在时钟沿从总线装入值。
- **MemEn**：允许内存的数据输出驱动共享总线。
- **MemW**：内存写控制，与 MA 的装入使能是不同信号。

这张图把 PC 放在寄存器 RAM 的内部位置 32，因此可以用 `RegSel=PC` 选它。这是微架构安排，不表示 RISC-V 新增了一个 `x32` 通用寄存器。

### `MA := PC` 的准确含义

这是“将 PC 当前的值装入 MA”的寄存器传送表示：

```text
RegSel = PC    选中已经保存在寄存器 RAM 内的 PC
RegW   = 0     本步不写寄存器 RAM
RegEn  = 1     PC 的值经寄存器 RAM 输出驱动共享总线
MALd   = 1     时钟沿把总线上的值装入 MA
```

对应的数据流：

```text
寄存器 RAM 中的 PC
    → 共享数据总线
    → MA 在时钟沿装入
    → MA 输出作为主存地址
```

PC 并不是先经过 RegSel 才“进入寄存器 RAM”：PC 的值已经存放在那里，RegSel 只是选择它。

MALd 的 `Ld` 是装入 MA；不是读取 MA，也不是读取或写入主存。`MA := PC` 本身完成的是地址保存，主存后续使用这个地址访问数据。

同一时刻通常只允许一个源驱动共享总线，但多个目标寄存器可以同时装入这个值。

## L02 第 25 页：Instruction Fetch

讲义给出的取指微程序：

```text
MA,A := PC
PC := A+4
wait for memory
IR := Mem
dispatch on opcode
```

若初始 `PC = 0x1000`：

- `MA,A := PC`：同时令 `MA=0x1000`、`A=0x1000`。除上面的控制信号外，还需要 `ALd=1`。
- `PC := A+4`：PC 更新为 `0x1004`；MA 仍保留本次取指地址 `0x1000`。A 为 ALU 保留原 PC 这个操作数。
- `wait for memory`：等待地址 MA 对应的内存读取完成，关注图中的 Busy 信号。
- `IR := Mem`：以 `MemEn` 驱动总线，用 `InstLd` 将读出的指令装入 IR；需要避免其他源同时驱动总线。
- `dispatch on opcode`：根据 IR 中的 opcode 选择后续微程序入口；这是微程序控制流程，不是直接改变普通程序的 PC。

结果是读取 `Mem[0x1000]` 中的指令，不是把数值 `0x1000` 写入内存。
